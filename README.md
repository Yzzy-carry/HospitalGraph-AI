# 联邦医院知识图谱AI

> 在「数据不出院」的前提下，让六家医院的知识图谱与诊断模型一起变强。
> 一个可现场运行、可逐项核验的联邦学习 + 知识图谱闭环演示系统。

参赛赛道：AI 创新应用挑战赛（Vibe Coding · 个人赛）
开发方式：与 AutoClaw 协同开发（全过程留痕见 `prompts/`）

---

## 一、这是什么

医疗数据最典型的困境是「数据孤岛」：每家医院都有病例，但受隐私法规与机构信任限制，原始数据基本出不了院；而单家医院数据量小，各自训练的模型都弱。本系统给出可运行的答案——**数据不动，模型动**。

系统由三层构成：

| 层 | 内容 | 关键点 |
| --- | --- | --- |
| 知识层 | 六院知识图谱（本院视图 / 联邦聚合视图） | 各院贡献可标注、来源可追溯 |
| 模型层 | 真实 FedAvg 联邦训练的诊断评分模型 | 六院本地训练 → 按样本量加权聚合 → 全局模型下发 |
| 应用层 | AI 辅助诊断 · 拍照分析 · 病历档案 · AI 问答 · 联邦训练演示 | 六个模块共用同一条「数据不出院」链路 |

### 核心数字（均为实测）

| 指标 | 数值 |
| --- | --- |
| 知识库规模 | 6 院 / **24 病种** / 61 症状 / 106 症状关联 / 53 药物 / 37 检查 / 106 预防 / 144 发病率 |
| 联邦模型 | **130 参数**（106 症状权重 + 24 病种偏置）· 15 轮 FedAvg |
| 训练损失 | **3.1781 → 0.5275** |
| 训练集准确率 | **90.8%** |
| 留出集准确率 | **86.0%**（n=172，训练未见样本） |
| 联邦 vs 最好单院 | **+13.6 个百分点**（90.8% vs 77.2%） |
| 差分隐私权衡 | 噪声 σ=0.2（ε≈24.2）精度仅降 1.5pp；σ=1.0（ε≈4.85）降 50.7pp |

> 全部为**合成模拟数据**（非真实患者数据）。这恰是联邦演示的合理前提——真实临床数据不允许出院。

## 二、快速开始

### 环境要求

- Windows 10/11
- Python 3.11+（本项目在 3.11.9 / 3.13 验证通过）
- MySQL 8.0
- 可选：网络（用于云端视觉识别与问答；离线时自动降级，核心功能不受影响）

### 步骤

```powershell
# 1) 获取代码
git clone <仓库地址> HospitalGraph-AI
cd HospitalGraph-AI

# 2) 安装依赖
pip install -r requirements.txt

# 3) 建库（含全量知识库数据，约 21 KB SQL）
#    方式 A：命令行
mysql -u root -p < db/init_hospital_graph.sql
#    方式 B：图形工具（Navicat / Workbench）直接导入该 SQL

# 4) 配置连接与密钥（复制模板后填写）
copy .env.example .env
#   编辑 .env：MySQL 密码、百炼 API Key（见下节）

# 5) 启动
python app.py
#   浏览器打开 http://localhost:5000
```

### 配置项

创建 `.env`（或直接设环境变量）：

```ini
# 数据库（与 app.py 的 DB 配置对应）
HG_DB_HOST=localhost
HG_DB_USER=root
HG_DB_PASSWORD=你的MySQL密码
HG_DB_NAME=hospital_graph

# 阿里云百炼（DashScope）——用于 AI 问答与拍照识别
BAILIAN_KEY=sk-你的Key
BAILIAN_VL_MODEL=qwen3-vl-plus        # 视觉模型（可留空用默认）

# 服务
HG_HOST=127.0.0.1                     # 局域网访问改成 0.0.0.0
HG_PORT=5000
HG_DEBUG=0                            # 生产/演示建议 0
```

> 不配置 `BAILIAN_KEY` 也能启动：问答与拍照识别会提示不可用，其余模块（诊断 / 图谱 / 联邦训练 / 病历档案）完全正常。

## 三、功能与验证路径

每条都可以现场复核，不是"概念演示"。

### 1. AI 辅助诊断（可解释）

- 点选症状 → 推理 → 展示鉴别诊断排名
- 每个结果**点开就是依据**：三因素拆解（症状匹配 60% / 本院发病率 20% / 严重度 20%）、各症状贡献占比、易混淆病种
- 可切换「联邦全局模型 / 基础版」对照，直接看出联邦带来了多少分差
- 结果可「采纳 / 修正」→ 沉淀为本地训练样本（数据不出院）→ 下轮训练自动并入

### 2. 知识图谱（双视图）

- 本院视图 / 联邦聚合视图切换，显示「本院 N 条 / 联邦 N+M 条」
- 各院贡献标注为**演示示意口径**（界面已标注，不冒充真实贡献）

### 3. 联邦训练（真实 FedAvg）

- 六院各自本地训练 → 只上传参数 → 中心按样本量加权聚合
- 含留出集评估（准确率 / 分类指标 / 混淆矩阵）与训练日志导出
- 可现场「再训一轮」，观察反馈样本并入后模型版本递增

### 4. 差分隐私（新增）

- 「差分隐私对比」按钮：同数据、同轮次跑多档噪声，输出**隐私预算 ε ↔ 精度**权衡曲线
- 机制：参数更新量逐院裁剪 + 高斯噪声（灵敏度 = 最大院权重 × 裁剪阈值）
- **只读实验**：不写入全局模型，可反复演示

### 5. 拍照分析

- 上传照片 → 全过程可见（质量检查 → 智能识别 → 相似病例对比 → 鉴别要点 → 护理与就医建议）
- **任意照片均可识别**（不限于示例库），识别结果落档并可「带着这次分析去问 AI」
- 图像识别为健康教育参考，不构成诊断（界面已声明）

### 6. 病历档案（跨院）

- 手机号核验认领档案 → 跨六院就诊时间线（哪家医院、什么科室、什么结论）
- 未就诊医院显示「暂无」，覆盖医院可点击筛选
- 诊断采纳与拍照分析会自动写入档案；AI 问答会引用本档案作答（界面上标注来源）

- 指出项目名含「联邦学习」却未真正使用联邦算法（老师指出的痛点，成为全项目转折点）
- 要求明确标注数据来源、评估数据规模承载能力（确立诚实标注规范）
- 提出「拍照分析」原创设想，并延伸出病例工作流与联邦数据量不足的讨论
- 提出「病历档案」与「跨院就诊」设想（「你在哪家医院看过病」）
- 审阅体检清单后圈定优先级，承认数据层面撑不住算法

## 六、数据与合规声明

- **全部医疗数据为合成模拟数据**（非真实患者数据），由确定性算法生成，可复现
- 演示照片为合成/公开示例图，不含真实患者信息
- 图谱「各院贡献」为**演示示意口径**（界面已标注）
- 拍照统计为演示级 k-匿名（k≥3）；院区隔离基于 token→医院映射级
- 本系统为**教学演示原型**，不构成医疗建议或临床诊断依据；如需就医请咨询执业医师
- 隐私保护声明：差分隐私为**演示级实现**（裁剪 + 高斯噪声），ε 为保守上界估计，未做严格的 RDP/矩会计

## 八、常见问题

**Q：没有 MySQL 能跑吗？**
不能，数据库是必需的。用 `db/init_hospital_graph.sql` 一条命令即可建好（含全部数据）。若想免安装 MySQL，可改用 SQLite，但需改动数据访问层（当前版本未提供）。

**Q：没有百炼 API Key 会怎样？**
问答与拍照识别不可用，其余模块（知识图谱 / 联邦训练 / 诊断推理 / 病历档案）完全正常——诊断推理用的是本地训练的联邦模型，不依赖云端。

**Q：为什么诊断模型只有 130 个参数？**
有意为之：可解释、训练秒级、演示稳定。本项目验证的是**联邦机制与数据治理**，不是冲击模型 SOTA。

**Q：为什么数据是合成的？**
因为真实临床数据不允许出院——这正是联邦学习要解决的问题本身。合成数据是可演示的合理前提，且全部标注清楚。

**Q：诊断推理真的用了联邦训练的模型吗？**
是。`/api/diagnose` 会读取 `data/fed_model.json` 的全局模型权重，对症状匹配做加权；界面上可切换「联邦全局 vN / 基础版」直接对比差异。
